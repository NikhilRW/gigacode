# Download an iOS IPA and build a POCO X4 APK

The app is `apps/expo` (Expo SDK 57 / React Native 0.86). Native projects are generated by Expo
Prebuild; do not commit or hand-edit generated `ios/` and `android/` directories.

## iOS: GitHub Actions Mac build

Workflow: **`.github/workflows/expo-ios-build.yml`**, shown as **Expo iOS build** in GitHub Actions.
It uses a GitHub-hosted **macos-26** runner, Node 22 and Bun 1.3.13. It checks that the selected Xcode
is at least **26.4**, required by SDK 57. The runner image must keep providing compatible Xcode,
CocoaPods and (for signed builds) Fastlane.

This follows the device-export pattern in `D:\RN_Practice\ios-dev`: an actual **iphoneos / arm64**
Release build is placed in `Payload/GigaCode.app` and zipped as an IPA. The separate simulator option
follows the simulator `.app` pattern in `rn_on_cloud_ios_simulator`. No streaming session is required
to create/download either artifact.

### Choose the artifact

| Workflow input | Output | Requirements / use |
| --- | --- | --- |
| `unsigned-ipa` (default) | `GigaCode-unsigned.ipa` | No Apple/Expo signing credentials. Must be re-signed before installation on an iPhone. |
| `signed-ipa` | `GigaCode-signed.ipa` | EAS-linked project, existing iOS preview signing credentials, Apple Developer membership, registered devices and the `EXPO_TOKEN` secret. |
| `simulator` | `GigaCode-simulator.app.tar.gz` | ARM64 iOS Simulator build, for an Apple Silicon Mac/cloud simulator. Cannot be installed on an iPhone. |

The unsigned/simulator paths explicitly run Expo Prebuild, CocoaPods, and `xcodebuild` in Release.
The signed path runs **EAS Local Build on that same GitHub Mac**, which performs Prebuild, CocoaPods,
native compilation and signing using the project's stored EAS credentials. This is not merely a JS export.
Release builds embed the app JS and editor DOM assets, so installed apps do not need Metro.

### Run and download

After the workflow file is on GitHub (on the default branch so the manual trigger is visible):

1. Open **Actions → Expo iOS build → Run workflow**.
2. Select the branch and artifact type.
3. Optionally enter your **HTTPS API origin**. Leave blank to configure it later in the app's
   **Connection** screen. A repository Actions variable named `EXPO_PUBLIC_API_URL` is also supported.
4. Start the workflow. When it succeeds, open its run page and download the artifact under **Artifacts**
   or use the link in the run summary.
5. Extract GitHub's outer artifact ZIP. Inside it is the `.ipa` or `.app.tar.gz` described above.

Artifacts are retained for **14 days**, subject to your repository's retention settings. The job runs
only when manually triggered. GitHub-hosted macOS usage/billing depends on your repository and plan.

Equivalent GitHub CLI commands, run against this repository:

```sh
gh workflow run expo-ios-build.yml --ref main -f artifact_type=unsigned-ipa
gh run list --workflow expo-ios-build.yml --limit 5
gh run download <RUN_ID> -n gigacode-ios-unsigned-ipa-<RUN_NUMBER>
```

No signing credential or API key belongs in `api_url` or `EXPO_PUBLIC_API_URL`; those are public app
configuration. Native fetch still needs a reachable API. A Codespace must be running, and its API port
must be accessible as explained in [CODESPACES.md](CODESPACES.md).

### Unsigned IPA installation

An IPA is a ZIP containing an iPhone app; creating that ZIP does not supply Apple's signature.
**`GigaCode-unsigned.ipa` cannot be installed directly by tapping it.** Re-sign it with an appropriate
Apple identity/provisioning profile using your chosen signing/sideload tool. That process must also
handle embedded frameworks and entitlements, including SecureStore/keychain access. Do not rename a
simulator archive to `.ipa`: its binary targets a different platform even when both say arm64.

### Set up the signed-IPA workflow option once

Run in **`apps/expo`** on your local terminal:

```sh
bun install --frozen-lockfile
bunx eas-cli login
bunx eas-cli init
bunx eas-cli device:create
bunx eas-cli build --platform ios --profile preview
```

Use your own Expo project and Apple Developer account. Choose/register the iPhones that must install
the app. The first interactive preview build establishes the certificate/provisioning and any required
configuration before later non-interactive builds. The checked-in `preview` profile uses internal
distribution; a signed IPA will install only where its provisioning permits.

Review and commit the resulting **public project configuration** (such as `extra.eas.projectId`/owner)
so the GitHub checkout can find your EAS project. Keep signing credentials out of Git. Create a personal
Expo access token and add it in **Repository Settings → Secrets and variables → Actions → Secrets**
as **`EXPO_TOKEN`**. Then select `signed-ipa` in the workflow.

Expired credentials or newly registered devices may require an interactive credentials/profile update
before CI can work again. CI does not bypass Apple provisioning or refresh devices automatically. If
using EAS environment secrets in addition to this project's config, EAS Local Build does not download
secret-visibility variables; supply required secrets through the job environment instead.

### Simulator archive

On an Apple Silicon Mac with an appropriate simulator runtime installed:

```sh
tar -xzf GigaCode-simulator.app.tar.gz
xcrun simctl install booted GigaCode.app
xcrun simctl launch booted com.gigacode.playground
```

The simulator must already be booted. The app uses the repository's current bundle identifier; use the
new identifier if you change `app.json`. An Intel Mac needs a separately built x86_64 simulator app.

## Android: local ARM64 APK for POCO X4

POCO X4 Pro 5G / X4 GT use ARM64-class hardware. Confirm the actual installed OS ABI over USB:

```powershell
adb devices
adb shell getprop ro.product.cpu.abi
adb shell getprop ro.product.cpu.abilist
```

Use **`arm64-v8a`** when it appears in that output. Enable Developer options and USB debugging on the
phone, and accept its USB authorization prompt. If multiple devices/emulators are connected, use
`adb -s <serial>` for device commands.

### Prerequisites

- Windows with **PowerShell 7 (`pwsh`)**, Node **22.13+**, Bun **1.3.13**.
- Android Studio / Android SDK, accepted SDK licenses, platform-tools, and a JDK compatible with the
  generated Gradle project. JDK 21 is available on the current development machine; ensure `JAVA_HOME`
  and PATH refer to your intended JDK.
- Set `ANDROID_HOME` to your SDK directory (commonly `%LOCALAPPDATA%\Android\Sdk`). Install the
  generated project's requested platform/build-tools/NDK/CMake versions through SDK Manager; SDK 57
  targets Android API 36. The first Gradle build downloads substantial dependencies.

### One-command build

Open PowerShell in **`apps/expo`**:

```powershell
bun install --frozen-lockfile

# Optional public API default. Otherwise configure Connection after installing.
$env:EXPO_PUBLIC_API_URL = 'https://your-api.example.com'

bun run apk:arm64
```

`apk:arm64` runs `scripts/build-android.ps1`. It runs Expo Prebuild without clearing an existing native
directory, then executes:

```powershell
.\android\gradlew.bat -p .\android :app:assembleRelease -PreactNativeArchitectures=arm64-v8a --console=plain
```

The architecture flag applies to this build; it does not permanently remove other architectures from
the app's configuration. The output is a **Release APK with embedded JS/assets**, not an AAB and not
a Metro-dependent debug build:

```text
apps/expo/android/app/build/outputs/apk/release/app-release.apk
```

Install it from that same `apps/expo` terminal:

```powershell
adb install -r ".\android\app\build\outputs\apk\release\app-release.apk"
```

Expo's SDK 57 template signs this local Release variant with its generated **debug keystore** by default.
It is suitable for your own sideload/demo, not Play Store distribution. An existing installation signed
with another key cannot be updated with this APK. Uninstalling it removes app data; preserve any drafts
you need first. For publishing, configure a real release key through a config plugin or use the existing
EAS build profiles with managed signing.

### Direct commands without the helper

From `apps/expo`, after installing dependencies:

```powershell
bunx expo prebuild --platform android --no-install --no-clean --skip-dependency-update react,react-native
.\android\gradlew.bat -p .\android :app:assembleRelease -PreactNativeArchitectures=arm64-v8a
```

On Linux/macOS the equivalent Gradle invocation is:

```sh
./android/gradlew -p android :app:assembleRelease -PreactNativeArchitectures=arm64-v8a
```

If Windows CMake/Ninja reports path-length or quoting errors, try a short checkout path such as
`D:\gigacode` before changing native build files. If the SDK location is missing, set `ANDROID_HOME`
in the terminal before the build. No Android emulator is required to produce the APK.

## Verification boundary

Workflow/script syntax, Expo configuration, lint and TypeScript can be checked on this Windows machine.
They do not create an IPA; Xcode runs on the GitHub Mac. Signed builds additionally depend on your Expo
project/token and Apple credentials. The Android command must complete Gradle compilation locally to
produce its APK. No GitHub workflow, signing-account operation or device installation is started just
by adding these files.
